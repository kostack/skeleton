# Milestone specification

A milestone groups tasks around a named delivery target within one project. A project can have many milestones. Each task can belong to one milestone or remain in the project backlog.

## Fields

| Field | Kotlin type | Contract |
|---|---|---|
| id | Long | Generated by the persistence adapter. Read-only. |
| projectId | Long | Required on creation. References an existing project and is immutable. |
| name | String | Required, nonblank display name, such as “Beta release”. |
| dueDate | LocalDate? | Optional calendar date in YYYY-MM-DD format. Defaults to null. |

## Milestone API

Use flat routes and the existing workspace authentication. Keep the model and repository contract database-agnostic.

| Request | Accepted input | Success |
|---|---|---|
| POST /milestones | JSON object with projectId, name, and optional dueDate | 201 with the milestone and a Location header pointing to /milestones/{id} |
| GET /milestones | Optional projectId query parameter | 200 with an array of milestones. Return an empty array when none match. |
| GET /milestones/{id} | Milestone ID | 200 with the milestone |
| PATCH /milestones/{id} | JSON Merge Patch containing name or dueDate, or both | 200 with the updated milestone |

Example response to POST /milestones:

```json
{"id":3,"projectId":10,"name":"Beta release","dueDate":"2026-12-01"}
```

POST consumes application/json. PATCH consumes application/merge-patch+json. Omitted fields retain their values. Sending `{"dueDate":null}` clears the date. Validate the complete patch before applying it. Return 400 for unknown or immutable fields, a blank or null name, or an invalid date. Return 404 for an unknown milestone on an item route or an unknown project during creation.

## Task integration

Add `milestoneId: Long?` to Task, defaulting to null. On task creation or update, a supplied milestone must exist (404 if missing) and belong to the task’s project (400 on mismatch). Apply this rule in the application service.

| Operation | Behavior |
|---|---|
| POST /tasks with milestoneId | Create the task in that milestone. Omitting milestoneId creates a backlog task. |
| PATCH /tasks/{id} with `{"milestoneId":3}` | Assign or move the task to milestone 3. |
| PATCH /tasks/{id} with `{"milestoneId":null}` | Return the task to the project backlog. |
| GET /tasks?milestoneId=3 | Return tasks in milestone 3. Combine milestoneId with other supplied filters using AND. |

Expose milestoneId and a nullable milestone summary containing id and name in task responses. A project-only task query includes both milestone and backlog tasks.

## Acceptance criteria

1. Create milestones in two projects. Filtering by either project returns only its milestones.
2. Rename a dated milestone and verify its date is preserved. Clear the date explicitly and verify the response contains a null dueDate.
3. Assign two tasks from the same project to one milestone. Both appear in its task list. Clear one assignment and verify that task appears in the project list and leaves the milestone list.
4. Attempt to assign a task to a milestone from another project during both creation and update. Both requests return 400. The failed create adds no task, and a failed update containing a valid title change also preserves the original title and milestone.
